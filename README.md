# Meme 币暴跌做空策略

> 暴跌发现 → Meme 币筛选 → 风险计算 → 执行（纸面/实盘）→ 持仓监控
>
> 交易所：Binance USDT-M 合约 ｜ 默认纸面交易，实盘需显式 `--live`

---

## 一、这个程序做什么

**核心逻辑是"事件型"而非"状态型"**：不等"跌到位了"，而是在**放量杀跌刚发生**
的那一天进场，然后分两段走：先做 2 天反弹，再做 5 天空头，捕捉第二段主跌。

针对你提出的三大致命风险，程序里的对应处理：

| 风险 | 程序中的处理 |
|---|---|
| 方向看对但仓位爆了 | 仓位由**止损距离反推**（风险预算 ÷ 止损距离），杠杆只是天花板不是目标；单笔风险默认 1% |
| 反向插针 / 定向爆破 | 止损放在**近期前高（真实阻力位）上方**而非固定百分比；止损宽度夹在 1.5%~12% |
| 资金费率损耗 | 资金费率转负（<-0.1%）触发**轧空预警并全平**；费率已为负的标的在选币阶段扣分 |
| 滑点与流动性陷阱 | 滑点按**盘口深度动态计算**，不是固定 0.3%；深度不足时自动惩罚；点差 >50bp 直接跳过 |
| 做空挤在地板上 | 信号源是"放量杀跌事件"而不是"价格已跌很多"——见第三节，这是回测里差别最大的一个改动 |

## 二、快速开始

```bash
pip install -r requirements.txt

python main.py scan              # 只扫描：当前信号 + 阶段 + 候选币 + 交易计划预览
python main.py scan --explain    # 附带列出被过滤掉的币及原因（调参用）
python main.py run               # 纸面交易主循环
python main.py status            # 查看持仓与盈亏
python main.py backtest --days 730          # 历史回测（含基准对照与事件型对比）
python main.py backtest --days 730 --sweep  # 追加阈值敏感性与分段检验
python selftest.py               # 强制触发信号，跑通选币→建仓→阶段切换→止盈止损全链路
```

国内网络直连 Binance 常被拒，程序会自动读取环境变量 `HTTPS_PROXY`，
也可以在 `config.yaml` 里显式写 `proxy: "http://127.0.0.1:7890"`。
镜像地址会按 `fapi.binance.com → fapi1..4` 自动轮换。

**第一次用请先跑 `backtest --days 730`** —— 它会给出这条策略在你自己的区间里到底
有没有超额，以及结论稳不稳。跑完再决定要不要实盘。

## 三、回测结果（近 730 天，19 只 Meme 币）

### 先看基准：不做这个策略会怎样？

| 持有期 | 随机一天做空 Meme 篮子的收益 | 胜率 | 样本 |
|---|---|---|---|
| 1日 | -0.13% | 52% | 749 天 |
| 3日 | -0.40% | 56% | 747 天 |
| 7日 | -1.09% | 60% | 743 天 |
| 14日 | -2.60% | 64% | 736 天 |

这段是熊市，**无条件做空 Meme 篮子本来就能赚**。所以任何策略都必须跑赢这条
基准线，而不是跑赢 0。下面所有"超额"都是减去这个基准之后的净值。

### 事件型信号（当前默认）：放量杀跌

**触发条件**：日线成交量 ≥ 20 日均量 × 1.8，且当日跌幅 ≥ 4%（放量杀跌）。
730 天里出现 16 次。

| 持有期 | 只做空收益 | 胜率 | 基准 | 样本 |
|---|---|---|---|---|
| 3日 | -0.16% | 53% | +0.40% | 15 |
| 5日 | **+3.64%** | 67% | +0.74% | 15 |
| 7日 | **+7.77%** | 73% | +1.09% | 15 |
| 10日 | **+5.94%** | 69% | +1.71% | 13 |
| 14日 | **+5.71%** | 77% | +2.60% | 13 |

注意 **3 日那行是负的**——放量杀跌后有 2 天反弹，直接做空正好吃在反弹上。

### 两段式：先做反弹，再做空

按 T0（放量杀跌当日）往后逐日看 Meme 篮子的走势：

| 持有 | 均值 | 中位数 | 上涨概率 |
|---|---|---|---|
| +1日 | +0.27% | -0.40% | 50% |
| **+2日** | **+1.02%** | **+1.75%** | **67%** ← 反弹窗口 |
| +3日 | +0.16% | -1.19% | 47% |
| +4日 | +0.06% | +0.05% | 53% |
| +5日 | -3.64% | -2.20% | 33% |
| +6日 | -4.09% | -4.78% | 33% |
| **+7日** | **-7.74%** | **-9.46%** | **27%** ← 主跌段 |
| +10日 | -5.94% | -6.51% | 31% |
| +14日 | -5.71% | -1.84% | 23% |

于是有了两种走法的对比（n=15）：

| 策略 | 平均 | 中位数 | 胜率 |
|---|---|---|---|
| 只做空 7 天 | +7.77% | +9.46% | 73% |
| **先多 2 天，再空 5 天** | **+9.86%** | **+10.41%** | **87%** |

**前后半段一致为正**：前半 +12.92%（胜率 80%，n=5）、后半 +8.33%（胜率 90%，n=10）。

机制：放量杀跌 → 强平盘出清 → 2 天反弹 → 恐慌盘二次进场 → 第 5~7 天主跌段。
反弹腿在 67% 的情况下赚钱，且它同时降低了做空腿的踏空风险。

程序默认走两段式（`config.yaml` 的 `bounce` 段），`enabled: false` 可关掉。

### 一个必须说清楚的现实：程序不总能在 T0 收盘就进场

上表的"从 T0 收盘进场"是回测口径。程序如果在 T0+1 盘中才启动（或 T0 收盘时没跑），
实际是从 T0+1 收盘进场：

| 反弹腿进场时点 | 平均 | 中位 | 胜率 |
|---|---|---|---|
| T0 收盘进（回测口径） | +1.02% | +1.75% | 67% |
| **T0+1 收盘进（现实口径）** | **+0.50%** | **-0.73%** | **47%** |

按 T0→T0+1 的涨幅分组：

| 漂移 | 样本 | 反弹腿均值 | 胜率 |
|---|---|---|---|
| < 0% | 9 | +0.96% | 56% |
| 0 ~ 2% | 4 | +0.82% | 50% |
| 2 ~ 5% | 1 | -3.30% | 0% |
| > 5% | 1 | -1.04% | 0% |

**结论：反弹若已在 T0+1 内走掉 2% 以上，反弹腿的收益基本被消耗光。**
所以程序有 `bounce.max_entry_drift`（默认 2%）保护：进场价较 T0 收盘价涨幅超过
这个值就**跳过反弹腿**，直接等做空腿。

这个取舍很划算：做空段才是主要贡献（+7.8%），反弹腿只贡献 +0.5%，
所以跳过反弹腿几乎不损失期望值，却能避开在反弹顶部接刀。

### 状态型信号（原来的做法）：等破位确认

| 持有期 | BTC均收益 | Meme均收益 | 做空Meme收益 | 胜率 | **超额** |
|---|---|---|---|---|---|
| 1日 | +0.84% | +2.01% | **-2.01%** | 26% | **-2.14%** |
| 3日 | +1.15% | +3.59% | **-3.59%** | 21% | **-3.98%** |
| 7日 | +0.02% | +1.52% | **-1.52%** | 42% | **-2.61%** |
| 14日 | -1.17% | +0.12% | -0.12% | 50% | **-2.72%** |

**等破位确认了再空，是负超额。** 信号触发后 BTC 反而在 1~3 日内涨了 0.84%~1.15%，
Meme 涨得更多，胜率低到 21%~26%。在熊市里"跌破关键位"往往是抄底资金进场的位置。

阈值扫描（7 日持有）也指向同一结论：

| 触发分 | 事件数 | 做空收益 | 超额 | 截尾超额 |
|---|---|---|---|---|
| 40 | 28 | +0.70% | -0.39% | +0.29% |
| **50** | 27 | **+1.78%** | **+0.70%** | **+0.89%** |
| 60 | 19 | -1.52% | -2.61% | -2.57% |
| 70 | 10 | -1.33% | -2.42% | -3.17% |

**"跌得越狠、指标越确认"的地方，恰恰是下跌衰竭点。** 所以程序默认改成事件型
（`crash.signal_mode: event`），状态型保留可用 `state` 切换。

### 三个反直觉的结论

**1）早进有效，等确认亏钱。** 你原始设想里"等破位信号确认再进"这一步，
是 alpha 的反面。60 分档位在前后两段行情里一致为负。

**2）头部 Meme 币不是 Beta 最高的，中盘币才是。**（与"优先做空 DOGE/SHIB/PEPE"相反）

```
WIF 跌β1.65   BONK 1.67   TRUMP 1.68   PENGU 1.78
PEPE 1.29     DOGE 1.33   SHIB 1.26
```

所以程序用 `min_downside_beta`（暴跌日跌幅放大倍数）而不是常规回归 β 做门槛。
**把 `screener.min_market_cap` 设成 5 亿美元会正好把表现最好的一批全筛掉**
（当前市场里 WIF 市值仅 $119M、BONK $181M、TRUMP $238M），默认值已按你给的
5000 万美元设置。

**3）做空要挑"费率仍为正"的币，反弹做多要挑"费率为负"的币。**
费率为正 = 多头拥挤 = 空头收租；费率为负 = 空头拥挤 = 做多方收租。
程序按持仓方向自动翻转这个偏好。

### 关于 FARTCOIN

它在回测里是最差的一个：7 日 -5.30%，14 日 **-13.32%**，胜率 37%。
这就是你担心的"庄家拉盘爆空头"，样本里真实发生过，不是理论风险。

### 必须说清楚的局限

- **样本量只有 16~28 次事件**，任何 1~2% 的差异都在噪声范围内。
- **全部样本来自一段熊市**。正超额有可能是"熊市里做空方向本来就对"带来的，
  而不是信号本身的择时能力。牛市里同样的信号大概率表现相反。
- **未计手续费与资金费**。一轮 4 个标的的组合交易，taker 往返约 0.4%，
  已经吃掉 +0.70% 超额的一大半。**扣费后这个策略基本没有剩余收益。**
- 篮子只含当前仍活跃的币，存在幸存者偏差。
- 回测未模拟滑点与插针，而这两项恰恰是 Meme 币实盘亏损的主要来源。

**所以：程序是工具，信号不是圣旨。** 默认配置里的风控（单笔 1% 风险、
2~4 个标的、日内 5% 熔断、12 小时冷却）比信号本身更重要。

```

selftest.py             全链路自检（纸面，不下真实单）
config.yaml             全部参数（密钥一律走环境变量，不写这里）
tests/                  离线单元测试（不联网，秒级回归）
local_bench/            本地 Parquet 回放与对照实验
docs/LOCAL_TESTING.md   测试规范与提交流程
memeshort/
  config.py             配置加载（含 YAML 数值强制转换）
  exchange.py           Binance 客户端：公开行情 + HMAC 签名下单 + 镜像轮换
  indicators.py         EMA/RSI/ATR/常规 β/下跌 β
  crash.py              暴跌信号：放量杀跌事件检测 + 状态评分 + 阶段计算
  screener.py           Meme 币筛选：硬过滤 + 多维打分（按多空方向翻转费率偏好）
  risk.py               仓位/止损/止盈/净盈亏比/深度感知滑点（多空通用）
  entry.py              盘中入场择时过滤器（15m 破位→弱反弹受阻→二次转弱）
  broker.py             纸面撮合 与 实盘下单（共用同一套决策逻辑，多空通用）
  notify.py             终端 + 日志 + Telegram + 企业微信/钉钉
  state.py              持仓与账户状态持久化（JSON，重启可恢复）
  engine.py             主引擎：事件 → 选币 → 择时 → 建仓 → 阶段切换 → 监控
  backtest.py           历史回测（状态型 / 事件型 / 两段式 对比）
```

### v2 升级内容

**核心策略**

| 模块 | 变更 |
|---|---|
| `entry.py` | 新增。15m 级别的「破位 → 缩量弱反弹受阻 → 二次转弱」入场过滤器，输出带 ATR 缓冲的局部反弹高点止损位。解决直接市价追空空在急跌底部的问题 |
| `risk.py` | 净盈亏比（Net RR，扣除往返手续费）；做空滑点改按**买盘深度**估算（卖单砸向买盘）；支持接入盘中结构止损位 |
| `broker.py` | 追踪止损（`trailing_activate_pct` / `trailing_callback_pct`）；分档止盈基数修正为 `0.5 + 0.5` 清仓零残留；保本止损含双边手续费；LiveBroker 移动止损时撤旧 STOP_MARKET 并按剩余仓位重挂 |
| `screener.py` | 修复负资金费率做空的惩罚符号（原先是加分）；新增买盘深度与「近 3 日相对 BTC 弱势度」因子 |
| `crash.py` | 修复 `score_at_event` 的截断逻辑，确保包含 T0 当天已完成的所有 4H K 线 |
| `engine.py` / `state.py` | 修复资金费多空方向；同步 `total_realized_pnl` 与纸面开仓手续费入账；跨日解除 `halted` 熔断标志 |
| `exchange.py` | **限速冷却**：解析服务端返回的真实封禁到期时间，冷却期内不发任何请求、不重试 |

**为什么「冷却期不重试」是必须的**：币安的 418 响应体里带精确封禁到期时间
（`banned until <epoch_ms>`），且**每次重试都会把封禁往后推**。
早期版本每 120 秒重试一次，结果一个 6000 秒的封禁被无限延长——实测中程序因此
连续数小时拿不到行情，持仓完全失去监控。现在冷却期内一个请求都不发。

**离线验证**

```bash
python -m unittest discover -s tests -v     # 7 项核心修复的离线回归，秒级
```

把本地 5m `*.parquet` 放进 `local_bench/data/` 后可做对照回放
（baseline / rebound_reject / trailing_wide 三套场景），产出
`route_attempts.csv`、`trades.csv`、`summary.json`。详见 `docs/LOCAL_TESTING.md`。

### 信号：事件型（默认）

**触发**：日线放量杀跌 —— 成交量 ≥ 20 日均量 × 1.8 且当日跌幅 ≥ 4%。
只用**已收盘**的日线（当日 K 线还在变，不能用来判定）。

状态评分（7 因子，归一化到 100 分）在事件型下退居为**确认条件**：
事件时刻的状态分需 ≥ 25（确认处在下跌趋势中），不再要求 ETH 双确认。

**确认必须用「事件时刻」的状态分，不是当前状态分。** 状态分衡量的是
「价格是否在局部低位 + 指标是否空头」—— 价格一反弹，「跌破区间下沿」
「日线破位」就不再计分，分数会从 64 掉到 21，拿它当确认线就恰好在
最该做反弹的时候把信号关掉。程序用事件当刻的数据窗口重算分数，
任何时候重跑结果都一样。

| 因子 | 权重 | 说明 |
|---|---|---|
| 4H 均线空头排列/死叉 | 2.5 | EMA20/EMA50，死叉比单纯排列权重高 |
| 跌破 N 根区间下沿 | 3.0 | 权重最高的破位因子 |
| 高位回撤 | 1.5 | 回撤超过 5% 起计分 |
| 放量阴线 | 1.5 | 量能 > 20 根均量 1.5 倍 |
| 缩量反弹 | 1.0 | 反弹无力 |
| 日线破位 | 2.0 | 日线跌破 20 日低点 |
| 资金费率多头拥挤 | 1.0 | 费率 > 0.03% |

切回状态型：`crash.signal_mode: state`（`BTC ≥ 50 且 ETH ≥ 40`，或 `BTC ≥ 78` 单边触发）。

### 阶段：两段式执行

以事件日 T0 为基准，程序自动推进阶段：

| 距 T0 | 阶段 | 动作 |
|---|---|---|
| +1 ~ +2 | `bounce` | 平掉空头腿，**做多**（反弹腿，风险减半、不加杠杆）；若价格较 T0 收盘已涨超 `max_entry_drift`（2%）则**跳过** |
| +3 ~ +7 | `short` | 平掉多头腿，**做空**（主跌段） |
| 其他 | `wait` | 不操作；窗口结束则按时间平仓 |

阶段切换靠 `(事件日, 阶段)` 做幂等键，同一事件同一阶段不会重复开仓。

### 选币打分

硬过滤（不满足直接出局）：市值区间、24h 成交额、合约上线天数、点差、资金费率异常。

打分（100 分）：资金费率拥挤度 30 + 下跌 β 30 + 流动性 25 + 前期涨幅 15。
**方向决定费率偏好**：做空偏好费率为正（空头收租），做多偏好费率为负（做多方收租）；
反方向的拥挤度会乘上惩罚系数（最多 -40%）。

### 仓位怎么算

```
风险预算     = 权益 × risk_per_trade          （做空 1%，做多 0.5%）
止损（做空） = 20日前高 × 1.005 与 ATR×1.5 取更近的，夹在 1.5%~12%
止损（做多） = ATR×1.5 为下限；20日前低已被击穿时不可作支撑
数量         = 风险预算 ÷ |止损 - 入场价|
实际杠杆     ≈ 风险预算 ÷ 止损宽度
```

**注意实际杠杆远低于杠杆上限**：1% 风险 ÷ 12% 止损 ≈ 0.08x。
Meme 币的宽止损决定了仓位自然就小，`max_leverage: 2.0` 只是天花板。
想让账户用得更满，要么调大 `risk_per_trade`，要么收紧止损——但后者会增加被插针扫掉的概率。

## 五、实盘上线步骤

> ⚠ **先读完第三节再往下走。** 回测显示这条策略的超额只有 +0.70%/笔（7 日），
> 扣掉手续费后基本归零，而且全部样本来自一段熊市 —— 20~30 个事件的样本量
> 不足以支撑"这个信号有效"的结论。**建议先用能亏得起的钱去验证信号，
> 而不是相信它。**

1. **先跑测试网**：把 `config.yaml` 里 `testnet: true`，用测试网的 Key 跑通全流程。
   测试网地址 `https://testnet.binancefuture.com`（代码已自动切换）。
2. **设置密钥**（**只给交易权限，不要开提现权限**）：
   ```bash
   export MEME_API_KEY=xxx
   export MEME_API_SECRET=xxx
   ```
3. **先跑纸面至少一周**，观察 `logs/` 下的日志和 `status` 输出，确认信号频率和持仓管理符合预期。
   重点看：触发次数是不是比预期少很多（默认阈值下大约每月一次）。
4. **用你自己的区间跑一遍 `backtest --sweep`**，确认结论在你的样本上成立。
5. **小资金实盘**：`python main.py run --live`，程序会要求输入 `YES` 二次确认。
6. 通知渠道在 `config.yaml` 的 `notify` 段配置；Telegram 用 `TELEGRAM_BOT_TOKEN` /
   `TELEGRAM_CHAT_ID` 环境变量，Webhook 用 `WEBHOOK_URL`。

### 实盘与纸面的差异

- 实盘下真实下单（逐仓 + 独立杠杆），交易所挂 `STOP_MARKET` / `TAKE_PROFIT_MARKET` 保护单。
- 实盘以交易所为唯一事实来源，每次轮询用 `positionRisk` 同步真实持仓。
- 实盘的成交均价由交易所返回；若与计划价偏离，会按真实止损距离重新核对风险。
- **纸面模型的滑点是估算值，不是真实成交价**。纸面跑出来的收益不能直接外推。

## 六、几个需要注意的地方

- **同一轮暴跌只开一次仓**：建仓后进入 12 小时冷却，避免在下跌途中反复加仓被轧。
- **日内亏损熔断**：当日已实现亏损达到权益的 5%，停止开新仓。
- **信号本身很弱，风控才是主要收益来源**：默认单笔风险 1%、最多 4 个标的、
  每日最多亏 5%。这些参数比触发阈值重要得多 —— 阈值从 50 调到 60 的影响，
  不亚于把风控放松一倍带来的影响。
- **状态可恢复**：`state/` 目录下的 JSON 保存了持仓与账户状态，程序重启后继续。
  `python main.py reset` 清空。
- **CoinGecko 免费接口有速率限制**，拉取失败会自动退回内置白名单。
- 币安对低价币用 `1000PEPE` / `1000000MOG` 这类前缀合约，程序已做归一化处理
  （不做这个处理会整体漏掉市值最高的一批 Meme 币）。

## 七、免责

这是一个策略框架和研究工具。回测结果不构成收益预期——样本量有限，
未计手续费与资金费，存在幸存者偏差。Meme 币合约存在极端的庄家控盘、
定向爆破和流动性消失风险，杠杆合约可能损失全部本金。
先用纸面和测试网验证，再决定是否投入真钱。
